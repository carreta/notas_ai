# Phase 4 — Hardening and Release

## Goal

Prove the integrated application is stable enough for the exercise release.

## Scope

- close integration defects;
- decide FR-009 implementation or explicit deferral;
- optional FR-011 only if core is stable;
- verify FR-012 sample/demo fixture;
- regression tests;
- error UX;
- security checklist;
- full quality gate;
- clean migration/install;
- documentation corrections;
- traceability matrix completion;
- release notes/tag candidate.

## Prohibited

Do not use hardening as an excuse for new product scope.

## Release evidence

Record:

- implementation commit;
- test count/assertions/results;
- formatter/static analysis;
- build;
- clean migrations;
- route inspection;
- manual acceptance;
- security checklist;
- known limitations;
- architecture deviations;
- dependency changes.
