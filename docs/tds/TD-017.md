## Possible changes to improve task distribution

The current distribution is functional; however, some changes can be made to reduce possible conflicts between Dev 1 and Dev 2, group related tasks and keep a more balanced workload.

| Task                                | Current | Proposed | Main reason                                         |
| ------------------------------------ | ------ | --------- | -------------------------------------------------------  |
| **FR-004 — Validate AI response**    | Dev 2  | **Dev 1** | Group AI request, validation and errors under Dev 1.     |
| **P4-2 — Error UX**                  | Dev 1  | **Dev 2** | Separate UX from integration and security tasks.         |
| **P4-4 — Clean migration/install**   | Dev 1  | **Dev 2** | Balance the workload in Phase 4.                         |
| **P4-6 — Release notes/tag**         | Dev 1  | **Dev 2** | Move a closing task to balance Phase 4.                  |
| **FR-011 — Health/readiness**        | Dev 2  | **Dev 1** | Keep AI Core verification together with Dev 1.           |
| **P4-8 — Documentation corrections** | Dev 2  | **Dev 1** | Compensate the redistribution of Phase 4 tasks.          |

### Advantages of the changes

- **Fewer code conflicts:** tasks that work on related components are grouped.
- **Clearer responsibilities:** Dev 1 would have greater responsibility over the AI Core flow and Dev 2 over other persistence and closing tasks.
- **Better distribution in Phase 4:** final tasks are split between both developers.
- **Less dependency within the AI flow:** FR-003, FR-004 and FR-008 would fall under the same owner.

### Disadvantages of the changes

- **Dev 1 would have greater technical complexity in Phase 2:** taking on FR-003, FR-004 and FR-008 concentrates much of the AI Core in a single developer.
- **Dev 2 would have more tasks in Phase 4:** although several are closing or verification tasks, it would have a greater numerical amount of tasks.
- **It does not remove all dependencies:** Dev 2 will still need to use the results generated and validated by Dev 1's AI Core.
- **It requires coordination:** before Phase 2, the contracts, data types and states used between the AI Core and persistence must be clearly defined.
