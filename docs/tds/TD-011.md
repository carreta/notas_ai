# TD-011 — Relative due-date representation and resolution

## Status

Proposed

## Context

Meeting discussions may contain relative temporal expressions such as "tomorrow", "next Monday", "next week", or "by the end of the month".

The system needs to determine how these expressions are represented in AI results and how they are converted into absolute dates when sufficient temporal context is available.

This decision is particularly dependent on the optional meeting time introduced by the meeting-time decision, since relative dates cannot be reliably resolved without a reference date/time.

Affected decisions:
- TD-002 — AI application contract.
- TD-006 — Result persistence.
- TD-009 — LLM provider/model strategy.
- TD-010 — Priority extraction/inference policy.
- Meeting time input decision.

## Constraints

- Relative dates must not be converted into absolute dates without an appropriate reference point.
- The system must preserve uncertainty when a relative date cannot be reliably resolved.
- Timezone must be considered when resolving date/time expressions.
- AI-generated dates must be distinguishable from dates explicitly stated as absolute dates.
- The representation must support persistence and UI presentation.
- Date resolution behavior must be deterministic enough to test.

## Options considered

### Option A — Resolve relative dates directly during AI analysis

Provide the meeting time as context and require the AI to return resolved absolute dates.

**Pros:**
- Simple downstream application logic.
- AI can use broader conversational context when interpreting expressions.
- Results are immediately usable by persistence and UI.

**Cons:**
- Date resolution becomes dependent on model behavior.
- Incorrect interpretations may be difficult to detect.
- Timezone handling must be communicated precisely to the model.
- Harder to guarantee deterministic behavior.

### Option B — Preserve relative expressions

Store the original relative expression without converting it to an absolute date.

**Pros:**
- Preserves the original meeting meaning.
- Avoids incorrect automatic date conversion.
- Simple persistence model.

**Cons:**
- Downstream consumers must interpret the expression.
- Difficult to sort/filter actions by actual due date.
- The meaning may become ambiguous over time.
- UI cannot reliably display an absolute deadline.

### Option C — Hybrid representation with explicit resolution metadata

Store the original relative expression and, when a reliable reference time exists, store the resolved absolute date together with metadata indicating how it was resolved.

**Pros:**
- Preserves original context.
- Provides a usable absolute date when resolution is possible.
- Makes uncertainty and inference visible.
- Supports auditing and debugging.
- Better suited for future changes to resolution logic.

**Cons:**
- More complex result schema.
- Requires clear distinction between explicit and inferred dates.
- Requires additional validation and testing.
- May require additional persistence fields.

La opcion C.
