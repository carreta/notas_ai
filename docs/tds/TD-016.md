# TD-003 — Laravel frontend

## Status

Proposed

## Context

The project needs a server-rendered web frontend integrated with the Laravel backend while keeping the MVP small and maintainable. The decision affects frontend architecture, UI development, testing, and team workflow.

## Constraints

- Laravel must remain the main application framework.
- The frontend must remain within the Laravel application.
- The backend must remain within the Laravel application.
- Avoid unnecessary frontend infrastructure or dependencies.
- The solution must support meeting submission, history, analysis results, and error states.

## Options considered

### Option A: Blade

**Pros:**

- Simple and lightweight.
- Minimal dependencies.
- Native Laravel integration.
- Easy to understand and maintain.

---

**Cons:**

- More manual JavaScript required for dynamic interactions.
- More difficult to build highly interactive UI.
- More frontend logic can become scattered between Blade and JavaScript.

### Option B: Livewire

**Pros:**

- Provides reactive UI while remaining within Laravel/PHP.
- Reduces the amount of custom JavaScript required.
- Integrates naturally with Laravel validation, authorization, and backend logic.
- Well suited for forms, status updates, history, and analysis results.

---

**Cons:**

- Adds Livewire as an additional dependency.
- Developers must understand Livewire's component lifecycle.
- Highly interactive client-side behavior may still require JavaScript.

## Decision

We Choose Livewire, as it provides the required interactivity while keeping the frontend within the Laravel ecosystem and minimizing custom JavaScript. It also fits the project's small scope and team objective of keeping the architecture simple.

## Consequences

- UI features will primarily be implemented as Livewire components.
- Backend validation and business rules remain in Laravel.
- The team must follow consistent conventions for Livewire components and state management.
- Automated tests should cover important component interactions and validation behavior.
- Additional JavaScript will only be introduced when Livewire is insufficient.

## Compatibility / migration

No existing schema or backend API changes are required.

The frontend will be implemented within the existing Laravel application using Livewire.
