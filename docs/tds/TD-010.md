# TD-010 — Priority extraction and inference policy

## Status

Proposed

## Context

AI analysis may identify actions, tasks, or follow-ups that appear to have different levels of importance or urgency.

The system needs to define whether priority should be explicitly extracted from meeting content, inferred by the AI, assigned using deterministic application rules, or left unspecified when the meeting does not provide enough information.

Affected decisions:
- TD-002 — AI application contract.
- TD-006 — Result persistence.
- TD-009 — LLM provider/model strategy.
- TD-011 — Relative due-date representation/resolution.

## Constraints

- The system must distinguish information explicitly stated in the meeting from AI inference.
- The AI must not represent uncertain priority assessments as factual statements.
- Priority values must use a controlled set of application-defined values.
- The policy must be deterministic enough to test.
- Missing or ambiguous priority information must have defined behavior.

## Options considered

### Option A — Explicit extraction only

Only assign a priority when the meeting explicitly provides enough information to determine it.

**Pros:**
- Minimizes unsupported AI inference.
- Easier to explain and audit.
- Lower risk of incorrect prioritization.
- Simple validation.

**Cons:**
- Many actions may remain without priority.
- Less useful when urgency is implied rather than explicitly stated.
- Requires the UI/application to handle unknown priority.

### Option B — AI inference

Allow the AI to infer priority from context, language, deadlines, dependencies, and other meeting signals.

**Pros:**
- Produces richer analysis.
- Can identify implied urgency.
- Reduces the number of actions without priority.

**Cons:**
- Higher risk of incorrect interpretation.
- Results may be subjective.
- More difficult to test deterministically.
- Requires clear confidence/uncertainty handling.

### Option C — Hybrid explicit extraction with constrained inference

Prefer explicitly stated priority information but allow AI inference according to defined rules when sufficient contextual evidence exists.

**Pros:**
- Balances accuracy and usefulness.
- Preserves explicit meeting information as the strongest signal.
- Allows inference where context is strong.
- Can define clear fallback behavior for ambiguous cases.

**Cons:**
- More complex policy.
- Requires clear rules for when inference is allowed.
- Inferred values may still be incorrect.
- Requires more comprehensive evaluation/testing.

## Decision

La opcion C es la preferible para garantizar en su mayoria que las prioridades estan bien, pero si los datos no se muestran se intentan inferir de los datos. Se debe avisar al usuario cuando esto sucede.
